Herdr 有多种状态路径。它们解决不同的问题。

## 实时持久化

普通的 detach 保持 Herdr 服务端运行。面板、shell、Agent、服务端、测试和命令进程在服务端内持续运行。

使用 `ctrl+b q` 分离客户端。稍后重新接入：

```bash
herdr
```

这是最强的持久化路径，因为原始进程从未停止。

## 快照恢复

如果 Herdr 服务端停止后再启动，原始的面板进程会丢失。Herdr 会恢复保存的会话形态：工作区、标签页、面板、工作目录、布局和焦点。

快照恢复不会保留运行中的 shell、服务端、测试或任意进程。无法使用更强恢复路径的面板会以新 shell 的形式恢复到其保存的目录中。

## 面板屏幕历史回放

面板屏幕历史在完全服务端重启后恢复最近的终端内容。它恢复的是 Herdr 能显示的内容，而不是旧的进程。

默认关闭，因为面板输出可能包含密钥、令牌、提示和命令输出。从 设置 > 实验 > 面板屏幕历史 启用，或使用：

```toml
[experimental]
pane_history = true
```

启用后，Herdr 将保存的面板历史存储在 `session-history.json` 中（与 `session.json` 并列）。将 Herdr 配置/会话目录视作终端历史。

## 原生 Agent 会话恢复

某些 Agent 可以恢复它们自己的对话会话。Herdr 可以使用官方集成上报的会话引用，在 Herdr 服务端重启后重启受支持的 Agent 面板。

通过以下方式启用：

```toml
[session]
resume_agents_on_restore = true
```

启用后，Herdr 仅恢复通过当前官方 Herdr 集成上报了原生会话引用的面板。

原生会话恢复需要以下 Herdr 集成版本或更新版本：

| Agent | Herdr 集成最低版本 | 恢复命令 |
| --- | --- | --- |
| Pi | `2` | `pi --session <path-or-id>` |
| Claude Code | `4` | `claude --resume <id>` |
| Codex | `4` | `codex resume <id>` |
| OpenCode | `2` | `opencode --session <id>` |
| Hermes Agent | `2` | `hermes --resume <id>` |

OMP 集成版本 `2` 上报 Agent 状态，但不为恢复上报原生会话引用。

运行 `herdr integration status` 检查已安装集成的版本。使用 `herdr integration install <agent>` 重新安装过期集成。

不受支持、缺失、无效、重复或过期的会话引用会恢复为保存面板目录中的普通 shell。

如果原生 Agent 会话恢复适用于某个面板，Herdr 会恢复 Agent 会话而不是为该面板回放保存的面板历史。

## 实时交接

实时交接用于需要替换运行中 Herdr 服务端的更新和远程接入流程。它请求旧服务端将运行中的面板转移到新服务端，以便面板进程可以在服务端替换期间保持运行。

这与快照恢复、面板历史回放和原生 Agent 会话恢复不同。交接试图保持当前进程存活。其他几种在旧服务端已停止后重建状态。

实时交接是实验性的，需手动启用：

```bash
herdr update --handoff
herdr --remote workbox --handoff
```

普通的 `herdr update` 和 `herdr --remote workbox` 默认使用正常的重启/停止流程。

`herdr update --handoff` 仅适用于由 Herdr 自身更新器管理的安装。Homebrew 和 Nix 安装通过各自的包管理器更新，因此 `herdr update` 在这些情况下被禁用且无法执行实时交接。

## 各种情况的存活情况

| 情况 | 进程继续运行 | 布局恢复 | 最近屏幕恢复 | Agent 对话恢复 |
| --- | --- | --- | --- | --- |
| 分离并重新接入 | 是 | 是 | 是，来自运行中的终端 | 是，因为进程从未停止 |
| 服务端重启 | 否 | 是 | 仅当启用面板屏幕历史时 | 仅当启用原生 Agent 会话恢复时 |
| 无 `--handoff` 的更新 | 兼容的服务端保持运行；需要重启的服务端可能需要停止/重启 | 重启后是 | 仅当启用面板屏幕历史时 | 仅当启用原生 Agent 会话恢复时 |
| 带 `--handoff` 的更新 | 对支持的运行中服务端尽力而为 | 是 | 是，如果交接成功则来自运行中的终端 | 是，因为如果交接成功进程保持运行 |
